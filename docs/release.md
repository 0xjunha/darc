# Darc Release Process

Darc releases are tag-driven from `main`.

## One-Time Setup

In the `0xjunha/darc` repository settings, confirm Actions can write release contents.
The release workflow uses the default `GITHUB_TOKEN` to create GitHub Releases.

## Release Channels

The first release pipeline publishes:

- GitHub Release archives for macOS and Linux.
- `darc-installer.sh`, generated by cargo-dist and hosted on the GitHub Release.

The supported install path is the shell installer hosted on the GitHub Release:

```sh
curl -fsSL https://github.com/0xjunha/darc/releases/latest/download/darc-installer.sh | sh
```

## Cut A Release

1. Prepare a normal release PR into `main`.

2. Update the workspace version in `Cargo.toml`.

3. Move the relevant `CHANGELOG.md` entries from `Unreleased` into a version section:

   ```md
   ## 0.1.0

   - ...
   ```

4. Run the local release checks:

   ```sh
   cargo +nightly fmt
   cargo clippy --workspace --all-targets --all-features -- -D warnings -W clippy::all
   cargo test --workspace
   dist plan --tag v0.1.0
   ```

5. Merge the release PR to `main`.

6. Tag the exact merged `main` commit:

   ```sh
   git checkout main
   git pull --ff-only
   git tag -a v0.1.0 -m "v0.1.0"
   git push origin v0.1.0
   ```

The release workflow refuses to continue if the tagged commit is not reachable from `origin/main`.

## Verify A Release

After the workflow completes, verify the installer:

```sh
tmpdir=$(mktemp -d)
curl -fsSL \
  https://github.com/0xjunha/darc/releases/latest/download/darc-installer.sh | \
  DARC_INSTALL_DIR="$tmpdir/bin" sh
"$tmpdir/bin/darc" --version
```

## Updating cargo-dist

`dist-workspace.toml` marks generated CI as `allow-dirty` because `.github/workflows/release.yml` has Darc-specific preflight checks before the generated cargo-dist jobs.

When updating cargo-dist:

1. Temporarily remove `allow-dirty = ["ci"]`.
2. Run `dist generate --mode ci`.
3. Reapply the Darc preflight job, `plan.needs`, pull-request path filters, and concurrency settings if the generator removed them.
4. Restore `allow-dirty = ["ci"]`.
